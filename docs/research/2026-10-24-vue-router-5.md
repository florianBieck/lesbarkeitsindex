# What vue-router 5 brings and requires for this SPA

Research for [#59](https://github.com/florianBieck/lesbarkeitsindex/issues/59), a ticket on the map [#46](https://github.com/florianBieck/lesbarkeitsindex/issues/46) (Nuxt 4 to a plain Vue 3 SPA). Done on 2026-10-24.

This note reports facts and trade-offs. It does not choose between file-based and hand-written routes. It also leaves the route clash ([#50](https://github.com/florianBieck/lesbarkeitsindex/issues/50)), API access ([#51](https://github.com/florianBieck/lesbarkeitsindex/issues/51)) and imports/type-check strategy ([#53](https://github.com/florianBieck/lesbarkeitsindex/issues/53)) to their tickets.

## Summary

1. **No code changes for a vue-router 4 app.** The migration guide says: "If you're using Vue Router 4 without unplugin-vue-router, there are no breaking changes". Every `BREAKING CHANGES` entry from 5.0.0 to 5.4.0 is in `vue-router/experimental` APIs. Every API this app uses behaves the same. **(verified)**
2. **What it requires:**
   - **`vue ^3.5.34`**, since 5.0.7. The lockfile has `vue@3.5.32`.
   - An **optional `vite ^7.3.0 || ^8.0.0` peer** (since 5.1.0). It resolves to the vite-plus-core alias, and pnpm prints a cosmetic "unmet peer vite (installed 1.4.0)" warning, as for plugin-vue in #47.
   - An optional `@vue/compiler-sfc` peer. pnpm linked it without a direct dependency. **(verified)**
3. **What's new is file-based routing in core.** The former `unplugin-vue-router` (now deprecated on npm, "Merged into vuejs/router") ships inside `vue-router`:
   - a `vue-router/vite` plugin;
   - a `vue-router/auto-routes` virtual module;
   - a generated route-map `.d.ts`;
   - the `definePage()` macro and the `<route>` SFC block.

   The docs do not mark file-based routing as experimental. Data loaders, param parsers, the route resolver and scroll restoration are marked experimental.

4. **The plugin works on vite-plus-core** (Vite 8 / Rolldown) for `vp build`, `vp dev` (with route HMR when a page is added), `vp test` and `vue-tsc`. **(verified)** One gotcha: the plugin's `root` option defaults to `process.cwd()`, not Vite's root. Run from the workspace root (`vp test` with `test.projects`), it found **zero routes** and wrote its `.d.ts` into `<workspace>/app/`. Setting `root` explicitly fixes this. **(verified)**
5. **Typed routes check names, not path strings.** With the generated map:
   - `router.push({ name: '/resultz' })` is a type error;
   - `router.push('/resultz')` and `<RouterLink to="/resultz">` are not, because string paths are typed `_LiteralUnion<paths, string>` and only gain autocompletion. **(verified)**

   This app navigates only by path strings. A hand-written table gets the same typing only through a manual `RouteNamedMap` augmentation.

6. **PrimeVue 4 `Menu` + `RouterLink`:** the app's current pattern carries over unchanged: a plain `RouterLink` with `v-bind="props.action"` in the `#item` slot, replacing `NuxtLink`.
   - It navigates client-side and closes the popup, in Chromium and under happy-dom. **(verified)**
   - PrimeVue 4 has no dependency or peer on vue-router.
7. **Unit tests:** `@vue/test-utils` 2.5.1 works with a real router (`createMemoryHistory`) and with `RouterLinkStub`. Lazy route components need `vi.waitFor`; `flushPromises()` alone is not enough. **(verified)**
8. **Knock-ons:**
   - **knip:** finds file-based pages only under `src/pages`. With `app/pages`, it reported all five pages as unused files until they were added as `entry`. The hand-written table needs nothing, and the `vue-router` ignore is not needed in either variant. **(verified)**
   - **`vp fmt --check`:** fails on the generated `.d.ts` unless it is in `fmt.ignorePatterns`. **(verified)**
   - **Bundle:** the main client chunk was the same size in both variants (328.18 kB), with the same five page chunks. **(verified)**
9. **Nuxt already ships vue-router 5 (surprise).** `nuxt@4.4.2` depends on `vue-router ^5.0.3`, and `vue-router@5.0.4` is in the lockfile today. The app still declares `vue-router ^4.6.3` itself, which resolves to 4.6.4. The generated `.nuxt/tsconfig*.json` files map `#vue-router` to that 4.6.4 copy. Nuxt calls vue-router 5's unplugin only when `experimental.typedPages` is on, and it is off here. So the claim that "the app is on 4.6.x via Nuxt" holds for the app's own dependency, but not for Nuxt's.

## 1. What 5.x changes for an app on 4.x

### What the release notes say

- **The migration guide** ([v4-to-v5.md](https://github.com/vuejs/router/blob/v5.4.0/packages/docs/guide/migration/v4-to-v5.md), identical live):
  - "Vue Router 5 is a transition release that merges unplugin-vue-router (file-based routing) into the core package. **If you're using Vue Router 4 without unplugin-vue-router, there are no breaking changes**."
  - Exception: "the _iife_ build no longer includes `@vue/devtools-api`". That only matters for `<script>`-tag use, not for a bundled app.
  - "Vue Router 6 will be ESM-only and remove deprecated APIs."
- **[CHANGELOG.md](https://github.com/vuejs/router/blob/v5.4.0/packages/router/CHANGELOG.md), 5.0.0 → 5.4.0.** The `BREAKING CHANGES` sections in 5.0.0-beta.1, 5.0.3, 5.0.7, 5.1.0 and 5.4.0 all touch experimental features only:
  - query params;
  - `miss()`;
  - `selectNavigationResult`;
  - param parsers;
  - query values as arrays "in the new experimental router".
- **Other 5.x changes worth knowing:**
  - The package is `"type": "module"` since 5.0.3, and still ships CJS (`index.cjs`).
  - 5.0.3 adds a deprecation warning for the `next()` callback in navigation guards. This app has no guards.
  - `@vue/devtools-api` moved to v8.
  - 5.2.0 added diagnostics such as `[VUE_ROUTER_R0004] No match found for location…`.
  - The `scrollBehavior` option is deprecated only on the experimental router (`src/experimental/router.ts`). The stable `createRouter` still takes it unchanged. This app sets none, and Nuxt's own scroll handling does not carry over to the SPA.
- **Install footprint.** `vue-router@5.4.0` has 16 runtime dependencies (`unplugin`, `chokidar`, `mlly`, `@vue-macros/common` and others, for the build plugin) and is 1.3 MB unpacked. `4.6.4` had 1 dependency and 0.66 MB. Hand-written-route users install these dependencies too.

### Requirements (npm metadata)

| vue-router     | `vue` peer            | `vite` peer (optional) | `@vue/compiler-sfc` peer (optional) |
| -------------- | --------------------- | ---------------------- | ----------------------------------- |
| 4.6.4          | `^3.5.0`              | none                   | none                                |
| 5.0.0 to 5.0.6 | `^3.5.0`              | none                   | `^3.5.17`                           |
| 5.0.7          | `^3.5.34`             | none                   | `^3.5.34`                           |
| 5.1.0          | `^3.5.34`             | `^7.0.0 \|\| ^8.0.0`   | `^3.5.34`                           |
| 5.2.0 to 5.4.0 | `^3.5.34 \|\| ^4.0.0` | `^7.3.0 \|\| ^8.0.0`   | `^3.5.34 \|\| ^4.0.0`               |

Optional peers `pinia` and `@pinia/colada` are only for the experimental data loaders. `vue@latest` is 3.5.44, and 3.5.34 was published on 2026-05-06.

### The five touchpoints in this app

| Usage today (Nuxt)                                                                                     | Under vue-router 5                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5 flat routes, no params, no names used, no guards, no meta                                            | Unchanged API. A hand-written table or the plugin both produce the same five lazy chunks. **(verified)**                                                                         |
| `NuxtLink :to="item.to" v-bind="props.action"` in the PrimeVue `Menu` `#item` template (`app/app.vue`) | Becomes `RouterLink` with the same attributes. See [§4](#4-primevue-4-menu-and-routerlink). **(verified)**                                                                       |
| `NuxtLink to="/"` in `pages/results.vue`                                                               | Becomes `RouterLink to="/"`. **(verified)**                                                                                                                                      |
| `useRouter()` + `router.push('/login')` in `pages/logout.vue` (auto-imported by Nuxt)                  | Same call. It needs an explicit `import { useRouter } from 'vue-router'` unless auto-imports stay; that choice belongs to #53. **(verified)**                                    |
| History mode (Nuxt's default web history)                                                              | `createWebHistory(import.meta.env.BASE_URL)`, unchanged from 4.x. Deep links still need the server's SPA fallback (#47: `vp dev`/`vp preview` have it; #49: the static servers). |

## 2. File-based routing in core

### The pieces

- **Vite plugin.** It is imported as `import VueRouter from 'vue-router/vite'` and must be listed **before** `vue()` (the docs say: "⚠️ Vue must be placed after VueRouter()"). Other bundlers use `vue-router/unplugin/*`.
- **Defaults** ([configuration.md](https://github.com/vuejs/router/blob/v5.4.0/packages/docs/file-based-routing/configuration.md)):
  - `routesFolder: 'src/pages'`
  - `extensions: ['.vue']`
  - `dts: './typed-router.d.ts'`
  - `importMode: 'async'`
  - `root: process.cwd()`

  The migration guide recommends `dts: 'src/route-map.d.ts'`, and the generated file says "It's recommended to commit this file".

- **Runtime.** `import { routes, handleHotUpdate } from 'vue-router/auto-routes'` is passed to `createRouter`. `handleHotUpdate(router)` hot-swaps routes in dev.
- **Generated names are paths:** `'/'`, `'/login'`, `'/results'` and so on. Nuxt's names were `index`, `login` and so on. This app references no route names, so nothing depends on this.
- **Per-page overrides:**
  - [`definePage({ path, name, meta, alias })`](https://github.com/vuejs/router/blob/v5.4.0/packages/docs/file-based-routing/extending-routes.md) in `<script setup>`. It is extracted at build time, so it cannot use variables, and `beforeEnter` is not supported.
  - Or a `<route>` JSON5/YAML block.
  - `definePage({ path: '/analysen' })` in `results.vue` changed the URL and kept the route name `/results`. **(verified)**
  - Without it, a page's URL is its file path. Moving a page (one possible outcome of #50) then means renaming the file or adding `definePage`.
  - The docs say `definePage` "can be imported from `vue-router`". In 5.4.0 it is exported only from `vue-router/experimental`, and is made global through the type stub `vue-router-auto-routes.d.mts`.
- **Folder conventions** ([file-based-routing.md](https://github.com/vuejs/router/blob/v5.4.0/packages/docs/file-based-routing/file-based-routing.md)): "as close as possible to Nuxt" (`index.vue`, `[id].vue`, nested folders, route groups, named views). The repo's `pages/__tests__/*.test.ts` produce no routes, because only `.vue` counts. **(verified)**
- **Auto-imports.** `vue-router/unplugin` exports `VueRouterAutoImports`, an import map for `unplugin-auto-import` (listed in the migration guide). It matters only if #53 keeps auto-imports. Not tested here.

### File-based vs hand-written, as observed

| Aspect                        | File-based (`vue-router/vite`)                                                                                                       | Hand-written table                                                                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Extra config                  | Plugin in `vite.config.ts` (with `root`, `routesFolder` for `app/pages`, `dts`), optional Volar plugins, knip `entry`, fmt ignore    | None                                                                                                                                           |
| Generated files               | Route-map `.d.ts` (136 lines for 5 pages), committed or regenerated by `dev`/`build`/`test`                                          | None                                                                                                                                           |
| Adding a page                 | Add a file. Routes and types update live in `vp dev` **(verified)**                                                                  | Add a file and a table entry                                                                                                                   |
| Path of a page                | File name, or a `definePage({ path })` override                                                                                      | Any string in the table                                                                                                                        |
| Route typing                  | Automatic `RouteNamedMap` (names, params, per-file `useRoute()` with the Volar plugin)                                               | Untyped unless a [manual `RouteNamedMap`](https://github.com/vuejs/router/blob/v5.4.0/packages/docs/guide/advanced/typed-routes.md) is written |
| What typing catches here      | Unknown **names** and params. Path strings get autocomplete only                                                                     | Nothing, unless typed by hand                                                                                                                  |
| Tests                         | Can import `routes` from `vue-router/auto-routes`. Needs the plugin in the test config, and a correct `root` from the workspace root | Import the table module                                                                                                                        |
| Client bundle                 | Main chunk 328.18 kB, the same five page chunks **(verified)**                                                                       | Same                                                                                                                                           |
| Closeness to today's `pages/` | Same folder and names, so no file moves                                                                                              | Pages stay, plus one new table file                                                                                                            |

## 3. Running on vite-plus-core (Vite 8 / Rolldown)

All of the following ran in `apps/fb` with vite-plus 1.4.0 and gave a single Vite in `node_modules/.pnpm`, with no upstream `vite` or `rolldown` installed:

- `vp build`: 5 lazy page chunks plus the route-map `.d.ts`. **(verified)**
- `vp dev`: history fallback, and `/@id/__x00__vue-router/auto-routes` serves the generated routes. Adding `pages/neu.vue` triggered `hmr update vue-router/auto-routes` and updated the `.d.ts`. **(verified)**
- `vp test`, with Vitest 5.0.5 and happy-dom, run from the app folder. **(verified)**
- `vue-tsc --noEmit`. **(verified)**
- `pnpm peers check` printed "unmet peer vite, Installed: 1.4.0", wanted `^7.3.0 || ^8.0.0` by `vue-router@5.4.0`. This is the same cosmetic warning #47 found for plugin-vue and Vitest. The optional `@vue/compiler-sfc` peer was linked (3.5.44) without a direct dependency. **(verified)**

**Gotcha: `root` defaults to `process.cwd()`.** The `resolveOptions()` function in [`src/unplugin/options.ts`](https://github.com/vuejs/router/blob/v5.4.0/packages/router/src/unplugin/options.ts) resolves `routesFolder` and `dts` against `options.root || process.cwd()`, not Vite's `config.root`.

- Running `vp test` at the workspace root, with `test.projects: ['apps/*']`, loads the app config with the workspace root as cwd. The result:
  - `routes` was empty;
  - all route tests failed with `[VUE_ROUTER_R0004] No match found`;
  - a stray `app/route-map.d.ts` was written at the workspace root. **(verified)**
- Setting `root: fileURLToPath(new URL('.', import.meta.url))` in the plugin options fixed it. **(verified)**
- `pnpm --filter … run` and `vp` run inside the app folder are not affected, because their cwd is the package.

## 4. PrimeVue 4 Menu and RouterLink

- PrimeVue 4.5.5 has no vue-router dependency or peer (npm metadata).
- In the `#item` slot, PrimeVue passes `props.action`: the `p-menu-item-link` class, `tabindex="-1"` and `data-pc-section="itemlink"`. It handles clicks on the surrounding `p-menu-item-content` element.
- **The app's current pattern, with `NuxtLink` swapped for `RouterLink`, worked:**

  ```vue
  <Menu ref="menu" id="overlay_menu" :model="items" :popup="true">
    <template #item="{ item, props }">
      <RouterLink :to="item.to" class="flex items-center" v-bind="props.action">
        <span :class="item.icon" />
        <span>{{ item.label }}</span>
      </RouterLink>
    </template>
  </Menu>
  ```

  - In Chromium (Playwright, against `vp dev`), clicking "Bisherige Analysen" changed the URL to `/results` without a document reload, rendered the page and closed the popup. **(verified)**
  - Under happy-dom, the rendered `<a href="/results">` carried PrimeVue's `p-menu-item-link` class and `data-pc-section`, and a click navigated. **(verified)**

- **The [PrimeVue 4 docs' "Router" example](https://v4.primevue.org/menu/) is slightly different.** It renders `router-link` with `custom` and `v-slot="{ href, navigate }"` around its own `<a :href="href" v-bind="props.action" @click="navigate">`, falling back to a plain `<a>` for items with `url`. Both patterns produce an `<a>` with the action props. The docs' pattern also handles external URLs in the same menu.
- **vue-tsc:** `item` is PrimeVue's `MenuItem`, which allows arbitrary keys, so `:to="item.to"` type-checks under typed routes too. **(verified)**

## 5. Unit tests with `@vue/test-utils`

- `@vue/test-utils` 2.5.1 peers only `vue`, `@vue/compiler-dom` and `@vue/server-renderer` `3.x`.
- **Real router.** Pass `createRouter({ history: createMemoryHistory(), routes })` in `global.plugins`, next to PrimeVue, then `await router.push(...)` and `await router.isReady()` before `mount`. This tested the Menu navigation and `logout.vue`'s `useRouter().push('/login')`. **(verified)**
- **Stub.** `global.stubs: { RouterLink: RouterLinkStub }` mounts `results.vue` without any router, and `RouterLinkStub.props('to')` reads the target. **(verified)**
- **Lazy routes.** Route components are lazy (`() => import(...)`), so a navigation does not finish after `flushPromises()`. Asserting on `currentRoute` right away failed, and `await vi.waitFor(...)` fixed it. **(verified)**
- **Importing the generated routes.** In the file-based variant, a test can import `routes` from `vue-router/auto-routes`, because `vp test` reuses the app's `vite.config.ts` plugins (#47). That breaks from the workspace root unless `root` is pinned ([§3](#3-running-on-vite-plus-core-vite-8--rolldown)).
- Today's frontend tests mount `index` and `admin` pages and two components, none of which touch the router.

## 6. knip

- **Today:** `knip.config.ts` sets `ignoreDependencies: ['vue-router']` for `apps/frontend`, because `vue-router` was referenced only from generated `.nuxt/*.d.ts` files. In both lab variants `vue-router` is imported from `router.ts`/`main.ts`, and knip reported no dependency issue for it. **(verified)**
- **knip 6.42.1's `unplugin-vue-router` plugin** (`dist/plugins/unplugin-vue-router/index.js`):
  - It turns on when `unplugin-vue-router` is a dependency, or when `vue-router` is one **and** a `.d.ts` whose first 300 bytes contain `Generated by vue-router` exists at `*.d.ts` or `src/**/*.d.ts`.
  - It then adds the production entries `src/pages/**/*.{vue,md}`.
  - It does not read `routesFolder` or `dts` from `vite.config.ts`.
- **Effect on this repo's layout.** With `app/pages` and `app/route-map.d.ts`, the plugin stayed off. knip reported the five pages as **unused files**, because they are only reachable through the virtual `vue-router/auto-routes` module. Adding `entry: ['app/pages/**/*.vue']` for the workspace cleared it. **(verified)** A `src/pages` + `src/*.d.ts` layout would match the plugin's defaults; that was read from the source, not run.
- **Hand-written table:** the pages are reached through the table's `import()` calls, and knip needed no config. **(verified)**
- The `vue-router/auto-routes` import was not reported as unresolved. **(verified)**

## 7. vue-tsc, `vp fmt` and `vp lint`

- **Volar plugins.** The two optional Volar plugins go in `vueCompilerOptions.plugins` as `vue-router/volar/sfc-typed-router` and `vue-router/volar/sfc-route-blocks`.
  - `sfc-typed-router` types `useRoute()` per page file.
  - It prints `[vue-router] No rootDir specified…` unless `compilerOptions.rootDir` (or a plugin option) is set. `"rootDir": "."` silenced it. **(verified)**
  - The migration guide's tsconfig example includes `rootDir`.
- **String paths are not checked** ([`typed-routes/route-location.ts`](https://github.com/vuejs/router/blob/v5.4.0/packages/router/src/typed-routes/route-location.ts), `RouteLocationAsString`):
  - Without a route map, a string location is `string`.
  - With a map, it is `_LiteralUnion<paths, string>`, so any string is accepted.
  - `router.push('/resultz')` passes vue-tsc, while `router.push({ name: '/resultz' })` fails. **(verified)**
- **Without the generated `.d.ts`:** on a fresh checkout, before any `dev`/`build`/`test` run, `vue-router/auto-routes` still resolves to the package's type stub with an empty map.
  - vue-tsc passes, but name checks are off. The `@ts-expect-error` on the bad name became "unused". **(verified)**
  - So vue-tsc only checks routes if the file is committed or generated before the type check.
- **`vp fmt --check`** (Oxfmt) flags the generated `route-map.d.ts`. **(verified)**
  - Its header carries `// oxfmt-ignore`, but that covers only the next statement.
  - Reformatting it is undone on the next generation, so it belongs in `fmt.ignorePatterns`, like the unplugin `.d.ts` files in #47.
- **`vp lint`** passed on both variants with defaults. **(verified)**

## 8. This repo today

- **`apps/frontend/package.json`** declares `vue-router ^4.6.3`, locked at 4.6.4, and `vue ^3.5.25`, locked at 3.5.32. Moving to 5.4.0 means raising `vue` to at least 3.5.34 to meet the peer.
- **`nuxt@4.4.2`** declares `vue-router ^5.0.3`, locked at 5.0.4 with `@vue/compiler-sfc@3.5.32`. Both majors are installed today.
  - Nuxt imports `createRoutesContext` from `vue-router/unplugin`, but only uses it when `experimental.typedPages` is on. It is not on: `.nuxt/types/` has no `typed-router.d.ts`.
  - `.nuxt/tsconfig*.json` maps `#vue-router` to the app's 4.6.4.
  - Nuxt sets `vite.resolve.dedupe: ['vue-router']`. Which copy ends up in the built client bundle was not checked.
- **Routing touchpoints:**
  - 2× `NuxtLink` in `app/app.vue`, inside the Menu template;
  - 1× `NuxtLink` in `pages/results.vue`;
  - `useRouter` in `pages/logout.vue`;
  - no `useRoute`, `navigateTo`, `definePageMeta`, middleware or route names anywhere in `app/` or `e2e/`.

## Open uncertainties

- **Which vue-router Nuxt bundles today** (4.6.4 or 5.0.4) was not checked in `.output`. It does not affect the SPA.
- **`vue-router` 5 alongside `unplugin-auto-import`/`unplugin-vue-components`** (`VueRouterAutoImports`) was not tested. It matters only if #53 keeps auto-imports.
- **knip detecting `src/pages`** automatically comes from reading knip's source, not from a run.
- **Pinning `root`** was checked for `vp test` at the workspace root. Other root-level entry points (`vp run`, editor tooling that loads `vite.config.ts`) were not tried.
- **Vue Router 6** is announced as "ESM-only" and will "remove deprecated APIs". The generated-types format is marked `TODO(v6)` in `vue-router-auto-routes.d.mts`. No release date was found.
- **Test environment:** the lab ran on Node 22.23.4 (the repo pins 22) and pnpm 11.9.0. The Chromium check used Playwright against `vp dev` only, not `vp preview` or a static server.
